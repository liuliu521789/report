4. 增加企业微信通知任务表 outbox
目标

当前问题
业务接口里直接?await tryNotify...。例如订单提交财务审核后同步发送企业微信。?
财务审核通过后也同步通知仓库。?

数据库表设计
新增表：
CREATE TABLE IF NOT EXISTS wecom_notify_jobs (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  event_type VARCHAR(64) NOT NULL,
  template_code VARCHAR(64) NOT NULL,
  to_user TEXT NOT NULL,
  variables_json JSON NOT NULL,
  biz_type VARCHAR(64) NULL,
  biz_id BIGINT UNSIGNED NULL,
  status ENUM('pending','sending','sent','failed','dead') NOT NULL DEFAULT 'pending',
  retry_count INT NOT NULL DEFAULT 0,
  max_retries INT NOT NULL DEFAULT 5,
  next_retry_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  last_error TEXT NULL,
  wecom_response_json JSON NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  sent_at DATETIME(3) NULL,
  PRIMARY KEY (id),
  KEY idx_wecom_jobs_status_next (status, next_retry_at),
  KEY idx_wecom_jobs_biz (biz_type, biz_id)
) ENGINE=InnoDB;
新增函数
在?server/src/lib/wecomNotifyOutbox.js?中实现：
export async function enqueueWecomNotify(pool, {
  eventType,
  templateCode,
  toUser,
  variables,
  bizType,
  bizId
}) {}
要求：

校验?templateCode?非空。


校验?toUser?非空。


variables?存 JSON。


返回 job id。

修改业务调用方式
当前这类调用：
await sendWecomTemplateMessage(pool, {
  templateCode,
  variables,
  toUser
});
改成：
await enqueueWecomNotify(pool, {
  eventType: 'sales_order_submit_finance',
  templateCode,
  toUser,
  variables,
  bizType: 'sales_order',
  bizId: orderId
});
worker 逻辑
worker 每隔 5 秒拉取：
SELECT * FROM wecom_notify_jobs
WHERE status IN ('pending','failed')
  AND next_retry_at <= NOW(3)
ORDER BY id ASC
LIMIT 20
发送前更新为?sending。
发送成功：
status = sent
sent_at = NOW(3)
wecom_response_json = 企业微信响应
发送失败：

retry_count + 1


如果未超过?max_retries，status 回到?failed


next_retry_at?按退避策略递增


超过次数改?dead

退避策略：
第 1 次：1 分钟
第 2 次：5 分钟
第 3 次：30 分钟
第 4 次：2 小时
第 5 次：6 小时
验收标准

业务操作成功不再依赖企业微信接口是否可用。


企业微信失败后会自动重试。


数据库能查到每条通知的状态。


发送失败原因可见。

8. 一键发货绑定具体操作人
目标
知道是谁在企业微信里点击了“完成发货”。
当前问题
企业微信发货 token 只包含?purpose?和?orderId。?
执行发货时?shipped_by、updated_by、状态日志 actor_id 都是?NULL。?
推荐方案
优先方案：
企业微信 OAuth 获取当前访问者 UserID
流程：
确认页打开
  -> 如果没有 code，跳转企业微信 OAuth
  -> 获取 wecom_userid
  -> 根据 users.wecom_userid 找系统用户
  -> 发货时写 shipped_by = user.id
备选方案
如果短期不做 OAuth：

每个接收人生成独立 token。


token 中带?wecomUserid。


发货时记录 token 中的 wecomUserid。


如果能匹配系统用户，则写?shipped_by。

验收标准

发货状态日志能看到具体操作人。


订单?shipped_by?不再是 NULL。


无法识别身份时至少记录 IP、UA、wecomUserid/token jti。
